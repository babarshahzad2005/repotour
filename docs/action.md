# GitHub Action

The Repotour action keeps a codebase tour in your repository current. On every release (or when you run it by hand), it regenerates the tour and opens a pull request named **Update codebase tour**. If the tour did not change, it opens nothing. Later runs update the same pull request instead of opening new ones.

## Setup

1. Add `.github/workflows/tour.yml`:

   ```yaml
   name: Codebase tour

   on:
     release:
       types: [published]
     workflow_dispatch:

   permissions:
     contents: write        # push the repotour/update-tour branch
     pull-requests: write   # open or update the pull request

   jobs:
     tour:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v7
           with:
             fetch-depth: 0   # required: hotspots and ownership read the full history
         - uses: babarshahzad2005/repotour@v1
   ```

2. In **Settings > Actions > General > Workflow permissions**, enable **Allow GitHub Actions to create and approve pull requests**.

That's all. Repotour's cache is saved between runs, so after the first run only new commits are read.

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `path` | `TOUR.md` | Where the tour is written, relative to the repository root. |
| `format` | `md` | `md`, or `html` for a self-contained page. |
| `llm-api-key` | empty | Turns on AI summaries of key files. Pass it from a secret, for example `${{ secrets.GROQ_API_KEY }}`; see [AI summaries](configuration.md#ai-summaries). |
| `python-version` | `3.12` | Python used to run Repotour (3.11 or newer). |
| `token` | `github.token` | Token used to push the branch and open the pull request. |
| `dry-run` | `false` | `true` generates the tour and prints the diff without opening a pull request. |

Outputs: `changed` (`true` if the tour differs from the committed one) and `pull-request` (the pull request's URL).

## Notes

- **Pinned version.** The action installs Repotour from its own release, so `@v1.2.0` always runs Repotour 1.2.0. Use a full version tag or a commit SHA if you want updates only when you choose them.
- **CI on the tour pull request.** GitHub does not start workflows for pull requests opened with the default `github.token`. If your branch protection requires checks, pass a fine-grained personal access token or a GitHub App token as `token`, or close and reopen the pull request to trigger them.
- **Shallow clones** are refused with a message asking for `fetch-depth: 0`, because a tour built from a partial history would be misleading.
- **Summaries in CI.** With `llm-api-key`, the contents of up to 15 key files are sent to the configured provider on each run that changes them. Configure the provider in `.repotour.yml`; Groq is the default.
- **Hand-written files are safe.** If `path` exists and was not generated by Repotour, the run fails with exit code 4 instead of overwriting it.
